## 4. W2-08 grounding adjudicator design

Goal: lift grounding from 85.5% to at least 95% on the labelled set, without moving call 1 beyond 0.19 per turn by much.

1. **Rules first (exists).** `derive/ground.py`: span located, number, unit, date and name present, negation and modality kept, speaker matches.
   Precision is 1.0 on both labels; it decides 61% of items.
2. **Quote check (new, free).** Require the extractor to return the supporting `quote`. Verify it is a substring of the cited line after
   normalisation. If not, the item is `unsupported` with no model call. This moves many currently "undecided" items to decided.
3. **CPU adjudicator (exists as `decider`).** Make it the default tier instead of lexical overlap, and use a multilingual NLI model.
   Lexical overlap rejects only same-language text (`write.py:154-158`), which is why non-English fails.
4. **LLM tier (new `ground_adjudicator: llm`).** For items still undecided, send ONE call per window on a dedicated `ground_judge` role (worker tier, thinking off):
   - Input: the numbered cited lines and the list of claims `{id, text}`.
   - Output: a JSON array `{id, verdict: supported|partly|unsupported, quote}`, schema-constrained like `prompt_v2`.
   - The quote from the judge is verified by step 2 again, so a judge cannot ground a claim with an invented span.
   - Book it under stage `grounding_adjudicate`, add it to `window_stages` (#13), and cap it to one call per window.
   - Fire it only if at least one item is undecided and the language is not covered by the CPU decider.
   - Fold it into the coverage call when both fire.
5. **Decision rule.** `partly` and `unsupported` follow `ground_action` (`drop` or `tentative`). Undecided after the LLM stays `uncertain` and is kept (as now).
6. **Measurement.**
   - Report accuracy per language and per tier; a single 85.5% hides which tier fails.
   - Expected cost is +0.19 calls per turn only on windows with undecided items. If undecided is 39% of items, most windows fire it, so set a target of at most 0.3 of windows and waive the rest explicitly.
   - Gate: at least 95% on the labelled set AND coverage and MAB-CR non-inferior.

## 5. Test-suite split that works on Windows

Today: `tests/unit` 6,944 tests in 446 files, `evals/tests` 1,548, about 11 min serial. Parallel runs risk MemoryError (the S16 crash).

- **Tiers by marker, no new dependency.** Add `lib` (pure, `tests/unit/lib`, fast), `wiring` (`tests/unit/wiring`, 50 files, engine-booting, slowest), `unit_rest` and `evals`. Run `lib` and `schemas` on every save, the rest in CI.
- **Shard script instead of xdist as the default.** `scripts/shard_tests.py` runs N (default 3) `python -m pytest <dir shard>` subprocesses and merges exit codes. Shards are directories, balanced by file count and by a timing file from the last run (`--durations`). It uses `subprocess` only, so there is no fork/spawn trouble on Windows.
- **Optional `pytest-xdist`.** `-n 3 --dist loadfile` works on Windows (execnet spawn). Cap workers at 3 and never run beside a GPU batch. Needs two checks first, since a process-global changes behaviour:
  - the cost ledger global (#15),
  - the `READ_LEGS` registry side effect (#17).
- **Memory.** Keep 175 MB per worker in mind, add `PYTHONHASHSEED`/`MALLOC` nothing special, but add a `conftest` fixture that closes every `Engine` a test opens (a leak shows as growth across the suite) and a `MEMSPINE_TEST_MAXRSS_MB` guard that skips heavy fixtures above a threshold.
- **Do not run suites while a GPU screen is queued** (owner rule already in `SCREENS.md`); the shard script should refuse if `v2_queue.state` shows a running screen.
