# Schema sessions 1 and 2: versioning policy and trust boundary (owner, 2026-10-13)

Sessions 1 and 2 of `SCHEMA_AGENDA.md`. These answers constrain every object in `memspine.schemas` (MOD-01) and the
extraction compiler (W2-06a). Fields are not frozen here; later sessions fix them.

## Session 1: versioning policy (ER-33 B)

| # | Question | Owner's answer | Recommended? |

| S1-1 | Compatibility tiers | **Three tiers.** *Durable*: events, records, outbox rows, erasure manifests. ## Conditions that make S1-3 and S2-3 consistent with the rest of the plan

Claude proposed these conditions so the two non-recommended answers do not break decided contracts. They are subject to
the owner's veto.

1. **Reserved names win over `extra="allow"` (S1-3 vs S2-1, ER-32).** The model-output schemas (tier: internal) allow
   unknown fields. The compiler (W2-06a) has a fixed reserved-name list: `id`, `*_id`, `scope`, `tenant`, `user`,
   `trust`, `provenance`, `verified`, `status`, `epoch`, `generation`, `recorded_at`, `lineage`, `fingerprint`. Any
   reserved name in model output makes that item invalid under S2-2, so it is dropped and logged. It is never stored as
   an extra field. Other unknown fields from the model are kept in an `extras` map on the assertion. That map is not
   indexed and not used by supersede, graph or profile logic.
2. **Unknown fields on durable records (S1-3 vs ER-33).** Durable records keep unknown fields verbatim, and upcasters
   pass them through. A field that becomes known in a later version must be added through an upcaster that validates
   its old free-form values. The frozen fixtures include one record carrying an unknown field.
3. **New kinds get a safe default policy (S2-3 vs Q7 and ER-14).** A kind first seen from the model is registered in
   the kind registry (MOD-02) with:
   - provenance `model-proposed`;
   - cardinality *many*, so values coexist and never supersede (Q7: undeclared attributes coexist);
   - graph edges allowed only as generic `related_to` links;
   - exclusion from profile synthesis until declared.

   An operator declares a kind to give it a cardinality and policy. Kind names are normalised (lower-case, singular,
   snake_case) and capped per namespace (default 64 model-proposed kinds; over the cap they fall back to `other`), so a
   noisy model cannot flood the registry. The registry reports counts per kind.

## Effect on packages

- MOD-01: three tiers, `schema_version: int` on durable kinds, `extra="allow"`, and an export layout split into
  durable, public and internal.
- W2-06a: the compiler applies the reserved-name rule, item-level rejection with typed reasons, and the required
  citations.
- MOD-02: the kind registry accepts model-proposed kinds with the default policy, normalisation and cap above.
- R3 (rerank): fallback names recorded in `VERIFY.md` Q6.
