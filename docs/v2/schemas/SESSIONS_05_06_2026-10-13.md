## Session 5: assessment (ER-14 B)

| # | Question | Answer |
|---|---|---|
| S5-1 | Fields | Five separate fields:<br>- **`source_trust`**: set by the system from family and role.<br>- **`support`**: the count of independent families, plus the `restated` count (S4-3).<br>- **`binding`**: bound, partly or unbound.<br>- **`time_precision`**: the S6-1 enum.<br>- **`modality`**: asserted, negated, hypothetical, planned, reported or question.<br><br>The model's self-confidence is kept only as a hint (S2-1). |
| S5-2 | Who may supersede | An assertion can supersede the current value only if all three hold:<br>- `modality=asserted`<br>- `binding=bound`<br>- `source_trust` ≥ the current value's trust<br><br>Hypothetical, planned and reported assertions coexist as tentative. A newer assertion with lower trust becomes *contest*: both values are kept and the conflict is shown. |
| S5-3 | Graph edges | Assertions that are asserted and bound become normal edges. Hypothetical, planned and unbound ones become edges tagged `tentative`. Default graph reads exclude them, and they are shown only on request. |

## Session 6: time (I-2, ER-18)

| # | Question | Answer |
|---|---|---|
| S6-1 | Precision | instant, minute, hour, day, week, month, season, year, decade or unknown, plus an `approximate` flag. |
| S6-2 | Weak dates | **Anchor with a basis and never invent a date.**<br>- A relative phrase is resolved against the source time, with `basis=source_time` and the matching precision.<br>- If there is no source time, the phrase is kept as an unanchored relation.<br>- If there is no phrase, event time is left empty and source time is kept.<br><br>This replaces the window-start default at `windows.py:854` (W2-14). |
| S6-3 | Axes | Every assertion carries three times:<br>- **event time**: when it was true or happened, possibly an interval.<br>- **source time**: when it was said.<br>- **recorded time**: when it was stored.<br><br>An as-of read asking "what was true on X" uses event time. One asking "what did we know on X" uses source and recorded time. |
| S6-4 | Durations and relations | A duration is stored as a value plus a unit, with an anchor when one is known. A phrase such as "after X" is stored as a typed relation (before, after or during) to another assertion's id. Either is resolved into dates only when an anchor exists. |

Every temporal value carries `basis`: explicit, source_time, relation, inferred or none. The model proposes the text and a parsed candidate. The system computes the anchor, basis and precision (S2-1).

## Clarifications of S5-2 (coordinator, 2026-10-13, from X-05 labelling)
- Trust tiers for supersede: `default` (user, operator, system) above `low` (external, tool, web); equal tier may supersede.
- A closed past interval (event time ended before the current value began) coexists with the current value; it is history, not a conflict.
- Negation: a bound, asserted negation ("I no longer live in Utrecht") at cardinality one with trust >= current *retires* the current value (its event interval is closed) without a new value; with lower trust it contests; a hypothetical negation is tentative.
