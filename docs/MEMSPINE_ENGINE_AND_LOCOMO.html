3. Complete insertion flow: accepted turn to stored memory

Enter through write_messages (batched) or write (single)

write_messages(messages, namespace, session_id, group_id, valid_from) (E:4256) is the bulk door: one call per batch, ordered results. write (E:1663) is the single-record door every layer shares; write_ex returns a WriteOutcome with the action (added, merged, updated, contested, invalidated, rejected, quarantined). The REST route and MCP tools call these same methods (S/protocols/rest/app.py, S/protocols/tools.py).

Authenticate and validate

Engine itself does no authentication (ADR-017/018: authentication is the deployer's job). The optional reference middleware (rest.auth, ADR-041) supports API keys and OIDC JWT with a namespaces claim. The engine validates the namespace string (S/core/namespace.py), refuses memory_type='shared' (E:1741), and requires the memory type to be enabled (auto-enable closure in S/core/registry.py:44-56).

Stamp identifiers and time

record_id is a uuid4; content_fingerprint hashes the normalised content; recorded_at is strictly increasing (S/core/records.py:200-236); valid_from is the message timestamp if parseable, else the valid_from argument, else now. At the engine an unparsable stamp becomes now (the LoCoMo harness instead raises on an unreadable stamp, memspine_system.py:107-116) and the record is tagged ts_defaulted when read.skip_defaulted_dates is on (E:1783-1785). session_id becomes source.message_id for episodic records.

Pre-warm embeddings and prefetch neighbours

The batch is embedded once in chunks of embedding.batch_size (32) into the embedding cache (E:4549) so projectors hit the cache. When the firewall is on and the batch has at least two distinct contents, one batched vector query provides the eight nearest non-held neighbours for the embedding-outlier signal (E:4319). If pre-warm raises, nothing is written (retry-safe).

Apply the firewall, redaction and governance

_screen_write (E:4656-4718) runs in this order: redaction (off), governance tags (off), firewall (on), size/protected-key (off), hearsay cap, parent trust cap, principal reputation, inferred cap. The firewall is deterministic. Quarantined records are still projected into the indexes (and so consume retrieval slots) but are dropped at read by _gate_hits (E:5205).

4. Memory layers: what each stores, how it is written, which LLM calls it can make, how it is read

MemSpine has nine memory types (S/core/registry.py:23-35). They are not nine databases: each is a memory_type value on the same MemoryRecord (S/core/records.py:174-282), written through its own door, indexed by the same projectors, and read through the same _search. Only working, episodic and semantic are enabled in base/assistant (S/config/templates/base.yaml:41-52). Auto-enable closure: reflective needs episodic, prospective and associative need semantic, shared needs episodic or semantic (S/core/registry.py:44-56). No shipped template enables resource; no template binds any LLM role.

4.12 Which layers the LoCoMo arms exercise

7. Complete unified retrieval flow

Engine.read(query, namespace, mode, budget_tokens, top_k, replay_window) (signature near E:6562) is the one read door. It does not call a model by default and it does not answer: the answer is produced by the caller with a reader prompt (section 10). The other engine returns three independent strings (long-term, short-term, last-N) with no global rank; MemSpine returns one ranked, deduplicated, chronologically ordered context.

Validate and choose a mode

mode is replay (template default, base.yaml read.default_mode: replay), auto, compose, retrieve or full. auto first tries a whole-namespace chronological dump if it fits the budget (E:7517-7539), then routes aggregation questions to compose and the rest to replay. The planner (read.planner) is only consulted in auto (E:7549), so the LoCoMo replay arms never reach it.

9.6 Replay windows

  • In replay mode each surviving episodic hit is expanded inside its derived session (gap >= 30 min starts a new one): the hit first, then neighbours nearest-first, older first on a tie (_window_turns E:9391; expansion E:7618-7738). A neighbour that does not fit the remaining budget is skipped without costing the hit its place; windows of adjacent hits overlap and de-duplicate.
  • Size: read(replay_window=2) is an argument (default 2); replay_window_before / replay_window_after (SCH:574-575) override per side (BEST_dev: 2 before, 4 after); replay_window_unit: tokens uses per-side allowances (256 / 512 tokens); replay_budget_scaling (I20) shrinks window with the budget; replay_hits_first; replay_topic_segments (TextTiling); reply_links / reference_edges.
  • Final order: stable non-episodic records first, then turns sorted by chrono_key (valid_from, recorded_at, fingerprint, id). The reader therefore sees a chronological transcript with hits unmarked unless --memspine-mark-hits or context-order hits_first|hit_blocks is set in the harness.
  • LoCoMo caveat: all turns of a session share one stamp, so one dataset session = one derived session unless two sessions are < 30 minutes apart or a stamp failed to parse.

12.4 Caveats

  • I80 contamination: GROUNDED_LEGACY_QA_PROMPT quoted a LoCoMo gold answer and date; 8cebf97 replaced the default with without_example_dates(...). All absolute numbers above (74.5, 80.1, 80.4, 81.4, 82.7 dev) come from the contaminated prompt. Relative arm-to-arm deltas that share the prompt stand.

  • Single run per arm, one seed; screen deltas inside about +-5 net (dev) or +-12.9 net (full) are noise. Several earlier ablations overstated gains (one conversation 84.2% vs full 80.1%).
  • Thinking mode rejected: 63.2% vs 88.8% off on conversation 26 (+3/-42) because 43 answers hit the 4,096-token reasoning budget (A9). Thinking stays off.
  • Dev = most of the data: all ten conversations have been looked at during design; V03 blind sets (MemoryAgentBench Conflict_Resolution 400 q, ConvoMem 200 q) are wired but not run.
  • Not comparable with the combined engine: their document reports no LoCoMo result at all; reader (Qwen3-32B), extractor (Qwen3-235B-A22B) and judge differ. See the comparison file, section 2.2.
