# Perspective layer vs other memory engines

Date 2026-10-10. Read-only comparison; nothing here is implemented. Scope: how memory engines record **whose** statement a memory is, **about whom** it is, **how sure / what kind** it is, **how sensitive** it is, and **when** it holds, and how they use that at read time. "Planned layer" = the MemSpine perspective layer being built (gaps I39-I46, design doc not yet on origin; axes as briefed by the user).

Evidence rules: every engine cell cites `file:line` in a shallow clone (commit in the key below) or a prompt quoted from that file. "none" = searched for (speaker, subject, attribut, polarity, negat, hypothet, sensitiv, provenance, confidence, valid/invalid) and not found. Engines and the clone commits (all read-only, never run): Mem0 `b7ad69a`, Graphiti `a9ef13f`, Letta `5bcdd17` (repo is now a stub; code read from tag 0.16.7 as `letta-old/`), LangMem `48e3c11`, MemOS `a7367d0`, MemU `dc7bda8` (+ v1.2.0 prompts), Cognee `0ec7a9f`, A-Mem `ceffb86`, MIRIX `8cb06a6`, EverOS `fcd41b5`, Hindsight `44d5340`, Memobase `358c16b`, Supermemory `552803c` (docs + MCP only; the memory engine is closed, so claims come from `apps/docs`). Earlier code-traced material: `ECOSYSTEM_COMPARISON.md`, `ECOSYSTEM_MEMORY_TAXONOMY.md`, `ECOSYSTEM_PROMPTS.md`, `evals/analysis/SOTA_MEMU_MEMOS_LOCOMO.md`.

## 0. Summary for the implementing agent (forward this)

**Verdict.** No surveyed engine has more than three of the planned axes. Nobody models addressee, asker, reported speech, polarity, structured modality or hedging as separate fields, and nobody separates source trust from speaker certainty from extractor confidence. On those the planned layer **covers and enhances** the field. Nine things engines have that the planned layer, as briefed, **misses or does worse**. Fix them in the design; each has a gap row (I47-I55 in `evals/analysis/GAP_REGISTER.md`; I39-I46 are left for the layer itself).

| # | MISS / weaker than SOTA | Who has it | Fix in one line (generic, deterministic first) |
|---|---|---|---|
| X1 | No `agent` subject: facts about the assistant itself (its recommendations, actions, persona) are not split from facts about the user | Mem0 (`USER_` vs `AGENT_MEMORY_EXTRACTION_PROMPT`, `attributed_to`), Hindsight (`world` vs `experience`), MemOS ("assistant recommended"), LangMem ("user, itself") | `sub_kind` = self / addressee / third_party / **agent** / group / unknown. Default read for a user-profile question excludes `agent` subjects; assistant-turn rows get `agent` unless a user-acknowledgement promotes them |
| X2 | No `inferred` provenance and no explicit-vs-implicit preference rules | MemOS (`PreferenceTextualMemoryMetadata.preference_type`, explicit/implicit prompts), Supermemory ("derives", low-confidence review) | add `src=inferred` (written by K, never by W). Cap trust, never let it supersede an explicit statement, require at least 2 user turns of acceptance (MemOS rule), mark low-confidence inferred for review |
| X3 | Plans have no forward validity window and nothing expires | EverOS `Foresight` (start/end/duration_days), Graphiti (plan `valid_at` = mention time, "soft deadlines are not invalid_at"), Supermemory (time-based forgetting) | `modality=plan/request` carries `due_from/due_to` separate from `valid_from`; past-due plans render as `[past plan]`, drop below standing facts, are never deleted |
| X4 | No per-subject profile card | Letta `human`/`persona` blocks, Memobase topic/sub-topic slots, Supermemory static/dynamic profile per container | subject card = deterministic roll-up of `state` facts by `(owner, subject)`; cardinality-one slots; read as a short block only when the subject matches the question (I33 gate) |
| X5 | No per-namespace perspective context (who the owner is, who speaks, in what role) fed to extractor and reader | Supermemory `supportingContext` ("a third person watching a conversation between two people: what do they remember, and about whom"), Hindsight `agent_name` narrator + `retain_mission` | namespace-level `perspective_context` {owner, known speakers + roles, owner kin terms}; injected into extract prompts and used by the deterministic resolver |
| X6 | Sensitivity is one flat English lexicon tag (always `pii_tier >= high`), no grades, no judge | MIRIX `sensitivity` low/medium/high with a read-time filter; Cognee `detect_pii` (LLM, categories + severity) | grade low/medium/high from the category map; optional `sensitivity` task on the Decider; read-time **bar** (not exclusion) scales with grade |
| X7 | No participants / viewer predicate; no per-record visibility | EverOS per-sender fan-out (`user_memory.py:105-140`), MemOS `visibility` private/public/session | store `participants = {spk, addressees, subject}`; read predicate `viewer in participants or visibility == public`; optional per-record `visibility` |
| X8 | Kin and possessive terms are resolved relative to the owner, not the speaker | Graphiti ("Nisha's dad", `extract_nodes.py:104-113`), Hindsight ("Emily (user's roommate)") | resolve "my X" against `spk(m)`, store `relation_to_speaker`; derive `relation_to_owner` by composition only when `spk == owner` |

**Where the planned layer leads (b, enhances):** addressee, asker, reported speech with hearsay trust cap, polarity and modality as fields with read-time down-weighting, certainty split from trust, sensitivity applied at read, event time vs mention time with both kept, scope with three levels, lineage-bounded trust (THI). Section 3 gives the per-feature verdicts.

**Design note on opinions.** Hindsight shipped a separate opinion network and then removed it (`ECOSYSTEM_MEMORY_TAXONOMY.md:279`, migrations `g2h3i4j5k6l7` / `i4d5e6f7g8h9`; today `fact_type` is `world|experience|observation`, `http.py:515`). Keep opinion as `modality=opinion` on one store, not a second network.

## 4. Fix proposals (generic per I37)

All obey I37: no benchmark-specific strings or thresholds; deterministic first; the OpenDecider typed-question `Decider` (I28) is an optional resolver behind the existing port, never required, and never sees gold or category; every decision logged. LoCoMo and OP-Bench validate, they do not set numbers. Each fix is opt-in and default-off until the retrieval-only screen passes.

**X1 agent subject.** Fields: `sub_kind`. Deterministic: a turn with `role=assistant` and no named speaker sets `sub_kind=agent`; first-person on that turn refers to the agent, second-person to the user. Extract-side: do not extract user-profile facts from assistant text unless the next user turn is an acknowledgement (cue lexicon "yes / right / exactly / correct / sounds good / ok" and a decider `confirm` yes/no question; MemOS `mem_reader_prompts.py:5` and MemU `profile.py:95-96` apply the same rule). Read: user-profile questions (first-person or user-named) drop `agent` subjects; assistant-information questions ("what did you recommend") boost them. Test: unit on role switching; retrieval-only screen on BEAM/HaluMem assistant-information questions (I5), LoCoMo non-regression.

**X2 inferred provenance.** `src` gains `inferred`, written only by the K stage. Rules lifted from MemOS (`prefer_complete_prompt.py:83-137`): at least 2 user turns of behavioural support, never from assistant-only advice, never overrides or contradicts an explicit statement, one-off task needs excluded. Trust cap below `assistant-proposed`; rendered `[inferred]`; included in the I33 profile gate only. Review list `list_inferred(owner)` (Supermemory memory-review). Default off.

**X3 plan window.** Fields `due_from`, `due_to` (nullable) set only for `modality in (plan, request, wish)`; `valid_from` stays the mention time (Graphiti rule `extract_edges.py:183`: do not set `valid_at` to the future date; `edges.py:283`: soft deadlines are not invalid). Deterministic: reuse `core/event_date.py` / `temporal_resolve.py` against the mention date. Read: a plan whose `due_to` is before the question date renders `[past plan]` and sorts after standing facts; never deleted (history questions still need it). Duration fallback like EverOS `duration_days` when only "next month" is given.

**X4 subject cards.** Deterministic roll-up of `kind=state` facts per `(owner, sub(m))` into one line per attribute (cardinality `one` wins latest, `many` lists), built lazily on read from existing records, no LLM. Memobase-style per-slot `update_instruction` maps to the existing `extract_graph.cardinality` (I17). Injected only when `sub(m)` matches the question's persons (the `ReadPlan.persons` field already exists) and passes the I33 gate. Keeps profile blocks off by default (BEST).

**X5 perspective context.** Namespace config `perspective_context = {owner_name, speakers: {name: role}, kin_terms, language}` (all optional). Fed to extract prompts (as Supermemory `supportingContext`, Hindsight `agent_name` narrator) and to the resolver in X8; never contains dataset-specific values in code, only per-namespace data written by the caller or inferred from speaker labels at first write.

**X6 graded sensitivity.** Map the existing categories to grades by a fixed table (high: health, sexual orientation, credentials / regulated ids; medium: finance, legal, religion, politics, ethnicity; low: relationship disputes). Replace the flat `pii_tier>=high` with the grade (still never below the current tier). Optional Decider task `sensitivity` (typed `choice`, same port as I28) as a second opinion when the lexicon is silent on non-English or paraphrased text (Cognee's judge, MIRIX's LLM-assigned level). Read-time: for a sensitive record the relevance bar is the I29 / I37 self-calibrated margin plus a fixed step per grade (an additional `sensitive_margin_step` in the same portable sigma units, one value, not tuned); records of a sensitive subject are omitted from a question that is not about that subject. Keep `secret_value` apart from the searchable text, MIRIX style: the engine already masks via `core/redaction.py`; verify the embedding input is the masked text.

**X7 participants and visibility.** `participants` = union of spk, addressees, subject (names). Read predicate `viewer` (optional query arg): keep records where the viewer is a participant or `visibility == public`. Per-record `visibility` private / session / public (MemOS) defaults to namespace behaviour. Fan-out is a view, not a copy (EverOS copies each episode per sender; a predicate is cheaper and keeps one lineage).

**X8 possessor resolution.** Pattern pass over text: possessive pronoun plus kin / role noun ("my sister", "his dog") resolves to `"<spk>'s <noun>"` (Graphiti rule), stored with `relation_to_speaker`; `relation_to_owner` is composed only when `spk == owner`. Coreference "Emily (user's roommate)" (Hindsight) is the same output. Decider optional for ambiguous "they".

**X9 conflict key.** Extend the M4 key to `(owner, entity, attribute, sub, scope)` and treat a polarity flip as `contest`. A fact about a different subject, or a different scope (habit vs one-off), coexists (MemOS `mem_feedback_prompts.py:341`). Cognee-style pair judging stays optional: reuse the Decider with a `contradicts` question only on candidate pairs that already share the key.

## 5. Ideas worth adopting beyond the axes

1. **Opinion network (Hindsight) -> do not copy.** It was shipped and removed; use `modality=opinion` plus `corroborations` for confidence updates. The one thing worth keeping is Hindsight's observation `proof_count` / `history` (consolidator.py:9-11) as the opinion confidence, which MemSpine already has as `corroborations`.
2. **Edge invalidation (Graphiti).** `invalid_at` of the old fact = `valid_at` of the new one (`edge_operations.py:779`) is a clean rule for the supersede ladder and gives point-in-time reads; our record clocks already carry it. Add the invariant test: no two active `kind=state` records with cardinality one overlap in `[valid_from, valid_to)` for one `(owner, entity, attribute, sub)`.
3. **Mem0 separate agent memories.** Adopted as X1; Mem0's mistake to avoid is a single boolean `attributed_to`.
4. **Letta persona block / Hindsight disposition.** The agent's own persona as a pinned, read-only block per namespace (`read_only`, `block.py:36`): reuse `protected_keys` + `instruction_flag`; keeps the agent's identity out of the user's facts (X1).
5. **MemOS explicit vs implicit preference.** X2. Also its rule "use only the user's own statement as evidence when the user endorses an assistant item" (`prefer_complete_prompt.py:11`) is the user-confirmed upgrade condition.
6. **MIRIX knowledge vault.** Searchable `caption` separate from `secret_value` (`agent.py:1863`) and a read filter that excludes `high` from the prompt (`:1869`). For us: sensitive text never in the embedded string; the planned read-time bar is stricter than a hard exclusion because it still lets an on-topic sensitive record through.
7. **Supermemory `supportingContext`.** X5. Plus time-based forgetting (X3) and a review surface for low-confidence derived facts (X2).
8. **EverOS foresight.** X3; and its `evidence` text next to each plan (we have `turns`).
9. **Memobase `[mention date]` inside value text.** Not needed (fields), but a useful render format when two values for one slot are shown together: `value [mentioned D]`.
10. **Cognee dataset-level PII review at ingest, with a "never quote the data in the rationale" rule** (`detect_pii.txt`). Adopt the rule for any sensitivity decider log line: log label and category only, never the text.
11. **MemOS `usage` history per node** (`item.py:202`): record which queries used a record; a cheap signal to retire memories never used, out of scope for perspective but free once `ask(m)` exists.
